Beginner path

Ideas that turn up everywhere

A few ideas come up again and again, in every phase of a service. You do not need a long list of jargon. If you can use these in a conversation, you already have a solid start.

  • Defence in depth means not relying on a single lock. If one control fails, another should still stand.
  • Least privilege means giving people and systems only the access they need, only for as long as they need it.
  • Secure by design means building security in from the first conversation, not bolting it on at the end.
  • Keep it simple means the safe way should be the easy way. If the official path is too hard, people will go around it.
  • Confidentiality, integrity and availability are a short checklist: who should see this, how would we know if it was changed, and will it still be there when people need it?

One idea to avoid: hoping a system is safe because nobody knows how it works. Hiding the details is not the same as making something strong.

What GOV.UK recommends

Official design guidance puts the same ideas in government language.

  • NCSC secure design principles (opens in a new tab)

    NCSC's short official list of how to design security in from the start, including making compromise and disruption difficult, and making it easy to detect problems. They sit well beside the habits in the videos.

  • The Technology Code of Practice (opens in a new tab)

    The standard for technology in government service design. One of its points is to make things secure: follow NCSC guidance, use well-understood approaches, and fix problems promptly. This is the landing page for the whole code.

  • Secure by Design on security.gov.uk (opens in a new tab)

    The government's Secure by Design programme expects teams to build security into a service from the start, with a set of activities and evidence, rather than treating it as a late review.
