How to read it

Lanes show who or what performs the step. The eight pipeline gates appear as gateways, each tagged with its gate number so it ties back to the operating model tab. Where a shape maps to a control, the panel below offers a link straight to its detail.

Overview

Secure software delivery pipeline

From a change being raised to a conformant service running in the cloud, with every security gate shown where it actually sits. Five lanes carry the work: the delivery team, source control, the CI/CD orchestrator, the security tooling, and the cloud platform. Two pools beneath show where the process leaves the pipeline — to the Security Architecture tower for an exception or a risk position, and to the Security Operations tower for detection.

PIPELINE DEPENDENCY MODEL AND = every child required · OR = any path suffices · availability figures illustrative. The scale is coverage-weighted effectiveness — the share of in-scope changes where the control is both present and working. A box with children is scored by its weakest dependency and names it underneath; the combined product is in the detail panel. As-is is the position today; to-be is the position once the planned artefacts land. The gap between the two views is the investment case.

Weakest link, as-is —

Every branch is an AND gate, so a weak child pulls its parent down — which is why a composite box takes the score of its weakest dependency rather than the product of all of them. Select any box for its detail, or hover to highlight what it connects to. Availability figures are an illustrative opening position for a baselining conversation, not an assessment.

Framework references: NCSC CAF v4.0 (Objectives A–D) · GOV.UK Secure by Design (10 principles) · OWASP ASVS / SAMM · GovS 007. Tools are named by capability, not by product: source control, CI/CD orchestration, code quality, SAST, SCA, DAST, secrets management, infrastructure as code and a public cloud platform. Vendor names appear only as illustrative examples — substitute your own. Note the common trap that one vendor’s “SCA” means its static analyser rather than software composition analysis; say which you mean.
